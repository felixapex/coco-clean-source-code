# 组件与模板开发标准

版本：1.1.0  
Owner：组件与模板开发团队

## 1. 数据结构

### 1.1 页面模板

`[SHOPIFY][GATE]` 每个页面模板使用 JSON，必须包含：

```json
{
  "schemaVersion": 1,
  "sections": {},
  "order": []
}
```

- `sections` 的 key 是稳定区块实例 ID。
- `order` 只能引用 `sections` 中存在的 ID，不能重复。
- 每个模板最多 25 个 sections；平台可以设更低限制。
- 模板、区块、block 和 setting 的持久 ID 不得因显示名称变化而改名。

### 1.2 区块组

- header、footer 使用全站共享的 section group。
- 每组独立保存 `sections` 和 `order`。
- 每组最多 25 个 sections。
- 页面模板只引用组，不复制页头页脚实例。

### 1.3 Section schema

可添加区块必须包含：`name`、`settings`、`blocks`、`max_blocks`、`presets`，并按需使用 `tag`、`class`、`limit`、`enabled_on` 或 `disabled_on`。

- `limit` 只允许 1 或 2。
- `enabled_on` 与 `disabled_on` 不得同时出现。
- 可添加 section 必须至少有一个 preset。
- 每个 section 最多 50 个动态 blocks。
- 同一 section 不混用 local section blocks 和 theme blocks；本平台默认只使用 theme blocks。

### 1.4 Theme blocks

- 基础标题、文字、按钮、图片、视频、图标、分组、间距、产品信息均做通用 block。
- 可添加 block 至少有一个 preset。
- 支持嵌套，最大 8 层；禁止循环引用。
- 私有结构 block 不出现在通用添加列表，只能被指定父组件接收。
- static block 可编辑，但不可删除、移动或复制。

## 2. 设置类型

允许：`text`、`textarea`、`number`、`checkbox`、`radio`、`select`、`range`、`richtext`、`inline_richtext`、`image_picker`、`video`、`video_url`、`url`、`color`、`color_background`、`color_scheme`、`font_picker`、`text_alignment`、`product`、`product_list`、`collection`、`collection_list`、`page`、`link_list` 及已批准的 Shopify 兼容资源类型。

每个 setting 必须有 `type`、`id`、`label`；`id` 在所属 schema 内唯一且发布后保持稳定。

- `range`：数字型 `min/max/default` 必填，`step` 为数字。
- `select/radio`：`options` 使用 `{value,label}`；没有 default 时选第一项。
- `image_picker/video/product/collection/page` 不设置 default，渲染必须处理空值。
- `visible_if` 只依赖同级 setting，循环或无效引用直接失败。
- 不向商家开放任意 HTML、Liquid、JavaScript 或 CSS。

## 3. 可编辑范围

### 3.1 文字

文字来自 setting 默认值、实例值或 locale，禁止写死在渲染代码。开放：内容、语义角色、字号档、字重、行高档、字距档、对齐；不得允许任意 CSS 数值破坏响应式。

### 3.2 图片与媒体

图片设置至少支持：资源、alt、focal point、ratio、fit、position。视频支持封面、字幕、静音、循环和自动播放策略。首屏 LCP 图不得懒加载，非首屏默认懒加载。

### 3.3 有限外观设置

只开放：color scheme、对齐、按钮样式、圆角档、字号档、上下间距、图片比例。页面宽度由响应式容器控制，组件不得保存固定页面像素宽度。

## 4. 响应式与多语言

- 单一语义 DOM 优先，自动适配桌面和手机。
- 禁止固定截图坐标、固定整页宽度和依赖某一屏幕尺寸的绝对定位。
- 所有网格允许收缩、换行或按断点改变列数。
- 长文本、CJK、长德语、emoji、组合字符和 RTL 不得重叠或溢出。
- 根布局根据 locale 输出正确 `lang` 和 `dir`。
- 字体加载失败必须回退系统字体，不能导致不可读或严重 CLS。

## 5. 编辑器标记

区块根元素必须提供：

- `data-section-id`
- `data-section-type`

block 根元素必须提供：

- `data-block-id`
- `data-block-type`

可编辑内容提供 `data-setting="setting_id"`。一个设置控制多个节点时，所有节点使用同一 setting ID，但编辑器只显示一份设置。

## 6. 产品与动态资源

- 产品主 section 由 title、price、variant picker、quantity、buy buttons、description、media、pickup、recommendations 等 blocks 组合。
- 变体变化必须同步价格、媒体、SKU、库存、数量规则、阶梯价、selling plan、pickup 和按钮状态。
- Quick Add：单变体且无额外规则可直接加购；多变体或数量规则必须打开可访问弹窗并复用产品表单状态。
- 动态资源不存在时显示受控空态或隐藏，不得报错。

## 7. 版本与迁移

- 模板、section 和 block 保存 `schemaVersion`。
- setting ID、section type、block type 是持久身份，不能直接改名。
- 必须通过显式迁移映射完成重命名、拆分、合并和默认值变更。
- 未知新版 block 必须 fail closed，不能静默丢数据。

## 8. 组件门禁

以下任一发生即失败：schema 无效、无 preset、ID 重复、引用不存在、固定页面宽度、横向溢出、右侧留白、文字重叠、图片截图冒充资源、写死商家内容、缺少编辑标记、外部链接逃逸、动态空值崩溃、键盘无法操作。

## 9. 组件身份与组件库归档

组件开发还必须遵守 `09-最终导入底层执行标准.md`。每个候选保存 `componentKind`、来源名称、实际功能、名称匹配状态、schema、数据合同、三指纹及证据。

- `componentKind` 只允许 `section|theme-block`；两种层级禁止互相判重或直接替换。
- `familyId` 是四位数字字符串，表示语义功能家族，不表示页面位置。
- `componentTypeId` 使用 `0001-0001` 结构化字符串；英文稳定类型键另存 `canonicalTypeKey`。
- `presetId`、`componentVersion`、`componentInstanceId` 分别表示预配置、实现版本和页面实例。
- 分类只允许 `duplicate|preset|new-component|new-family|review-required`。
- 相同组件只保存一份公共实现；不同网站和页面保存独立实例与 settings/blocks。

三指纹是带算法版本的证据，不是越过硬合同的唯一依据。component kind、功能、数据、结构、交互、schema 和响应式合同必须同时满足合并条件。仅默认 settings/blocks 不同归为 preset；向后兼容实现升级归为新 version；现有合同无法表达的差异建立同家族新组件或新家族。

Coco 组件库 V1 确认前状态为 `coco-v1-pending`，组件开发只能产生候选和证据，不能自行分配正式编号。
