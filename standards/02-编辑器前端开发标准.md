# 编辑器前端开发标准

版本：1.1.0  
Owner：编辑器前端团队  
边界：本标准定义合同；当前导入器/组件任务不实现编辑器界面。

## 1. 编辑对象

编辑器读取统一的 template、section group、section、theme block、setting 和 global settings schema。不得解析组件私有 DOM 猜测设置；必须依赖稳定 ID 和 `data-*` 标记。

## 2. 必备能力

- 左侧组件树与预览双向选中。
- 添加、删除、复制、隐藏、排序 section/block。
- theme block 嵌套，阻止超过 8 层和不兼容类型。
- setting 面板按 schema 渲染并执行 visible_if。
- 桌面、平板、手机和自定义宽度预览。
- 浏览模式与选择模式分离，浏览模式允许真实点击本站链接。
- 选中轮播页、折叠项、标签页等隐藏内容时，组件进入可见编辑状态。

## 3. 会话、保存与发布

- Undo/redo 仅作用于当前未保存操作历史。
- 显式 Save 创建新 revision；保存后开启新的 undo 边界。
- Draft 与 Live 分离；预览草稿不能修改线上版本。
- 发布只引用一个已保存、已通过校验的 revision。
- 回滚创建新的 revision，不直接篡改历史。
- 保存请求携带 `baseRevision`；后台不一致时返回冲突，前端禁止静默覆盖，必须提示刷新、比较或重新应用。

## 4. 点哪改哪

点击 `data-section-id`、`data-block-id`、`data-setting` 时定位唯一节点。事件跨 iframe 时必须校验精确 origin 和 source。编辑器不得读取或执行商家注入的任意脚本。

## 5. 预览生命周期

组件必须支持 initialize、re-render、select、deselect、reorder、remove 和 destroy。每次重渲染先销毁旧监听器、observer、timer 和订阅，禁止重复绑定与内存泄漏。

预览与正式站使用同一渲染器和同一数据；仅编辑辅助层不同。禁止另做一个“看起来差不多”的编辑器渲染版本。

## 6. 错误与可恢复性

- schema 错误定位到 setting/section/block。
- 资源处理中显示 processing，不得假装 READY。
- 保存失败保留本地未保存修改。
- 网络中断允许重试，但同一 revision 请求必须幂等。
- 无权限、版本冲突、资源删除、目标路由缺失分别显示，不合并成“保存失败”。

## 7. 编辑器门禁

必须覆盖：点选映射、键盘操作、拖动排序、嵌套限制、visible_if、undo/redo、保存边界、Draft/Live、冲突、回滚、编辑/发布一致、移动预览、长文字、RTL、资源空态和重复初始化。

## 8. 保存接口合同

```json
{
  "siteId": "site_123",
  "templateId": "template_home",
  "baseRevision": 42,
  "clientMutationId": "uuid",
  "document": {
    "schemaVersion": 1,
    "sections": {},
    "order": []
  }
}
```

成功返回新 `revision`、校验摘要和保存时间。冲突返回 `REVISION_CONFLICT`、当前 revision 和冲突路径；schema 错误返回 `SCHEMA_INVALID` 及 JSON Pointer；资源未就绪返回 `RESOURCE_NOT_READY`。前端不得把失败响应显示为已保存。

## 9. 编辑会话状态机

```text
clean -> dirty -> saving -> clean(new revision)
                  |-> save_failed -> dirty
                  |-> conflict -> conflict_resolution -> dirty

draft_saved -> validating -> publishable -> publishing -> live
                              |-> blocked
```

浏览器关闭前存在 `dirty` 状态必须提示。自动本地恢复只保存未提交草稿，不能越过后台 revision 检查直接覆盖服务器。
