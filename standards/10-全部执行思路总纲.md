# 网站导入、组件化、验证与交付——全部执行思路总纲

版本：1.0.0  
状态：讨论结果汇总稿，供用户逐项确认  
用途：把此前分散在聊天、标准和实施计划中的执行思路合并成一份可阅读、可检查的总纲。

## 1. 最终目标

最终不是只复刻 Coco 或 Majestic，而是形成可持续使用的建站能力：

`输入网站 -> 识别来源平台 -> 进入对应导入器 -> 抓取原站证据 -> 识别页面和组件 -> 转换成可编辑模板 -> 逐块验证 -> 生成完整网站 -> 全站验收 -> 交付或发布`

输出必须同时满足：

- 网站可以完整打开，不是若干孤立链接。
- 页面、菜单、按钮、分类、产品详情和交互留在本站；允许的外部业务链接必须明确列入白名单。
- 电脑端和手机端自动响应式，不依靠用户分别制作两套内容。
- 网站由可复用、可编辑的组件组成，不是整页截图或写死 HTML。
- 每个结果都有来源证据、验证结果、耗时和可恢复状态。

## 2. 平台架构：分开识别，共享合同

Shopify、普通外网、Wix 以及未来新增渠道采用“平台适配器分开、平台中立核心共享”的架构。

### 2.1 必须分开的部分

- 平台探测。
- 抓取入口和路由发现。
- 来源结构解释。
- 来源组件名称、ID 和层级的提取。
- 登录、限流、动态加载和平台特有错误处理。

Shopify 不得失败后静默改走外网导入器；Wix 未实现时必须明确失败，不能冒充成功。

### 2.2 可以共享的部分

- 页面身份合同。
- 统一候选组件档案。
- schema/settings/presets 数据合同。
- 资源存储和本站路由合同。
- 组件命名核对、组件库去重、编号和版本。
- 公共浏览器运行能力。
- 逐块、整页和全站验收。
- 计时、恢复、熔断和交付清单。

因此，不做一个混杂所有平台选择器的“大导入器”，也不重复建设三套组件库。

## 3. 页面身份规则

每个页面保存三个互不替代的身份：

- `sourcePageId`：原站明确提供的页面 ID；没有就留空。
- `importPageId`：一次导入任务内部使用的临时纯数字 ID。
- `platformPageId`：本平台生成并永久保存的纯数字 ID。

规则：

- 同一页面重新导入必须复用原 `platformPageId`，不能重新生成。
- URL、页面名称、来源编号、canonical 和重定向关系分别保存，不能拿 URL 充当页面 ID。
- 来源 ID 与本平台 ID 永远不能互相覆盖。
- 匹配结果冲突时停止登记，不能猜测覆盖或生成第二个永久页面 ID。

## 4. 来源组件名称核对

所有渠道执行同一条业务规则：

1. 先读取原站能够提供的组件名称、类型、ID 和层级。
2. 再观察网页上的实际功能和交互。
3. 原名称与实际功能匹配：保存并复用原名称，同时映射到本平台标准名称。
4. 原名称缺失、过于宽泛或与功能不匹配：保留原名作为证据，按真实功能生成规范名称，并记录改名原因。
5. 证据不足：进入人工复核区，不自动进入正式组件库。

规范名称按“主要功能 + 内容形式 + 必要的特殊行为”生成，例如：图片横幅、视频横幅、轮播横幅、产品列表、图文并排、邮件订阅、购物车抽屉。

## 5. Shopify OS 2.0 兼容组件结构

我们的平台不是 Shopify，也不使用 Liquid；但组件和模板的数据结构尽量兼容 Shopify Online Store 2.0。

### 5.1 页面模板

- 每个页面使用 JSON template。
- 保存 `sections` 和 `order`。
- 页面最多 25 个 section。
- 页头和页脚使用全站共用的 section groups。

### 5.2 Section 与 theme block

- section 是页面主要区块。
- 基础内容单元统一使用可复用的 theme blocks，不混用 section 内私有 block。
- 通用小组件至少有一个 preset，才能出现在编辑器的添加列表。
- section 最多 50 个 blocks，可用 `max_blocks` 设置更低上限。
- section、theme block、preset、instance 和页面顺序是不同概念，不得混为一个编号。

### 5.3 Schema

section 至少支持：`name`、`tag`、`class`、`limit`、`settings`、`blocks`、`max_blocks`、`presets`、`enabled_on/disabled_on`。

setting 只使用确认过的标准类型，包括 text、textarea、number、checkbox、radio、select、range、richtext、inline_richtext、image_picker、video、video_url、url、color、color_background、color_scheme、font_picker、text_alignment、product、product_list、collection、collection_list、page、link_list。

所有 setting 都必须处理空值、错误值、默认值和 `visible_if`。不支持 default 的资源选择器不能伪造默认对象。

## 6. 可编辑数据范围

凡是商家以后合理需要修改、且原网站能够观察到的信息，都应进入结构化数据或 schema，不得写死在 HTML 中。

包括：

- 文字、标题、富文本、按钮文案和链接。
- 图片、视频、替代文本、宽高、原始比例、展示比例、裁切方式、焦点位置和清晰度。
- 字体、字号、字重、行高、字距、颜色、对齐和标题级别。
- 背景、配色方案、按钮样式、圆角、间距、列数、图片比例和显示条件。
- 菜单、产品、分类、页面和后台数据源的引用。
- 轮播、翻页、自动播放、弹窗、抽屉、折叠等行为设置。

全站品牌名、Logo、联系方式、社交账号、品牌色和字体放在全站设置中；业务价格、库存、订单等来自后台，编辑器只能选择或引用，不能伪造。

编辑器定位标记：

- section 根节点：`data-section-id`、`data-section-type`。
- block 根节点：`data-block-id`、`data-block-type`。
- 对应设置内容：`data-setting`。

## 7. 导入模式

- 自有或已授权网站：允许完整导入图片、文字、版式和交互，转换成可编辑模板。
- 第三方版式学习：只学习结构、区块组成、排列、比例和功能；图片、文字、品牌和 Logo 替换为平台或用户自己的内容，不保留原站版权内容和来源编号。

两种模式最后输出同一套页面、组件和模板合同。

## 8. 不可改变的逐步闭环

固定流程：

`保存原站标准答案 -> 公共资源验收 -> 建立页面身份 -> 识别并命名一个组件 -> 抽取可编辑 schema -> 生成一个组件 -> 原站与本地逐块对比 -> 点击该组件全部控件并比较结果 -> 检查本站路由和目标页 -> 通过后原子保存 -> 再做下一组件 -> 组装一页 -> 整页验收 -> 再做下一页 -> 全站总验收`

核心原则：

- 不能先生成几百页，最后才第一次发现公共组件错误。
- 一个组件失败，只修这个组件和依赖关系；通过的组件和页面不重跑。
- 一个页面失败，不得进入正式网站。
- 全站验收是最后确认没有遗漏，不是第一次发现基础错误。

## 9. 原站标准答案

标准答案不是只截一张整页图，而是保存可比较的结构化证据：

- 页面 URL、页面类型、DOM 层级和组件边界。
- 文字内容与排版计算值。
- 图片/视频原始资源、内在尺寸、展示尺寸、比例、裁切和焦点。
- 桌面与来源真实存在的手机布局。
- 所有可见控件的位置、类型、文字、状态和点击后的真实结果。
- 网络请求、路由目标、弹窗/抽屉/展开/局部更新等结果形态。

原站没有手机版本或无法取得手机基线时，不伪造“原站手机一致性”；只按本平台响应式门禁验收手机布局和交互。

## 10. 页面加载与资源处理

- 页面有什么才等待什么，禁止每页固定等待并不存在的商品列表或组件。
- 同时监听页面资源、DOM、字体、图片和布局变化；仍有有效变化就继续，稳定后立即结束，超过上限则明确失败。
- 已发现的资源先处理，不必等整页所有资源后才串行开始。
- 图片同时保存两层信息：原始文件的内在宽高，以及页面实际显示时的容器比例、裁切和焦点。
- 关键图片必须获取原始资源或可信资源响应，禁止用页面矩形截图冒充图片。
- 页头、页脚、Logo、字体、菜单图片、公共脚本和样式只抓取与验证一次，作为公共资源；但每页仍检查自身内容和该公共组件是否正确引用。

## 11. 错误分类、熔断与恢复

错误分三类：

- 网络错误：连接重置、超时、限流。
- 公共资源错误：页头、页脚、Logo、字体、菜单图片、公共脚本或样式失败。
- 页面/组件错误：文字、图片、布局、交互、schema 或路由失败。

硬规则：

- 连续 3 页出现同一网络错误，停止整批。
- 任意连续 10 页中网络失败超过 20%，停止整批。
- 公共资源失败一次，阻止所有依赖页面继续生成。
- 每个任务保存未开始、处理中、网络暂缓、等待公共资源、内容失败、交互失败、已验收状态。
- 中断后只恢复未完成或失败项，不重做已验收结果。

## 12. 小样本与并发

正式全站前先跑 8 类代表页面：首页、分类页、产品详情页、博客页、普通内容页、搜索页、登录交互页、复杂菜单页。

- 使用 1–2 路并发连续运行三遍。
- 三遍通过后按 2 -> 3 -> 4 路逐步扩容。
- 失败率升高时自动降级。
- 页面之间可以并行；同一页面内部按受控顺序完整执行交互，避免多个浏览器相互干扰同一状态。
- 不通过减少验收内容提速，而是通过缓存、位置索引、会话复用、增量恢复和安全并发让全量验收更快。

## 13. 四层自动验收

### 13.1 公共资源验收

检查页头、页脚、Logo、字体、菜单图片、公共脚本和样式；未通过不得开始依赖页面。

### 13.2 组件验收

检查文字、图片、视频、尺寸、层级、响应式、schema、空值、交互和可编辑性；组件边界不能吞入后续组件、页脚或页面脚本。

### 13.3 页面验收

检查整页布局、逐组件顺序、右侧留白、横向溢出、重叠、遮挡、本站路由闭包以及所有可见菜单、链接、按钮、输入、弹窗、抽屉、关闭控件的实际结果。

### 13.4 全站验收

检查全部纳入范围的路由、桌面端、手机端、链接目标、目标页存在性、组件档案、页面身份、重复组件判定和回归结果。

95% 视觉相似度只是附加指标，不能覆盖外链逃逸、按钮未点击、目标页不存在、关键图片错误、不可关闭弹窗、固定宽度、重叠或 schema 缺失等硬失败。

## 14. 组件库、自动查重与编号

### 14.1 身份

- `componentKind`：`section|theme-block`。
- `familyId`：四位功能家族，例如 `0001`；代表语义区域，不代表页面第几块。
- `componentTypeId`：例如 `0001-0001`；代表具体组件能力合同。
- `presetId`：例如 `0001-0001-P001`；代表同一组件的默认配置组合。
- `componentVersion`：同一实现和 schema 的版本。
- `componentInstanceId`：组件在某页面上的一次具体使用。

编号必须由中心组件库原子分配，按字符串保存，前导零不可丢失；名称改变不改编号，旧编号不得回收。

### 14.2 自动判定

候选组件按以下硬证据比较：

- 组件层级。
- 语义功能与能力。
- 数据来源和数据合同。
- 父子结构、允许子类型和数量限制。
- schema 可编辑能力。
- 交互状态机和点击结果。
- 响应式规则是否可由相同 settings 表达。

截图、名称、CSS 类、图片比例只作软证据，不能单独合并组件。

输出只有五类：

- `duplicate`：完全等价，复用已有组件，只新增来源和页面实例。
- `preset`：能力相同，仅默认 settings/blocks/布局不同。
- `new-component`：同一家族，但存在旧组件无法表达的能力差异。
- `new-family`：没有合适功能家族。
- `review-required`：证据不足，禁止自动合并。

### 14.3 Coco 作为第一版组件库

Coco 全站和组件档案全部验收前，只能保存候选，不分配正式家族和组件编号。Coco 内部归并后先给出稳定清单，用户确认后形成组件库 V1。以后第 11 个网站查询前 10 个网站积累的持久组件库，不依赖 AI 聊天记忆。

## 15. 编辑器与责任边界

当前导入器任务不负责开发编辑器界面或后台，但必须输出它们可直接使用的数据。

编辑器严格读取 schema 自动生成设置面板；修改 settings 后重新渲染并保存模板 JSON。业务规则不能写死在编辑器中。编辑器负责添加、删除、复制、排序、点选、即时预览、撤销重做、草稿、版本冲突、组件升级迁移和多语言界面。

后端负责商品、分类、库存、价格、账户、购物车、订单、上传、语言和发布接口。导入器不能伪造这些业务数据。

## 16. 计时与提速

每次运行记录：

- 平台探测时间。
- 路由发现时间。
- 公共资源准备时间。
- 页面抓取和标准答案生成时间。
- 组件识别、转换和生成时间。
- 逐块、整页和全站验收时间。
- 网络等待、重试、熔断、浏览器启动和关闭的次数与总耗时。

优化必须建立在真实分项数据上。不能用减少页面、少点按钮、抽查图片或跳过手机端来伪造提速。

## 17. 交付标准

完整交付包至少包含：

- 完整静态网站和全部本地资源。
- 页面、路由、组件和全站设置数据。
- 可离线启动的说明和必要运行环境。
- 抓取、处理、组件转换、页面生成和自动验收工具源码；不包含无关后台。
- 覆盖全部交付载荷文件的 SHA256 清单；清单本身按标准惯例单独校验或由整包 SHA256 保护。
- 全量验证脚本，不得只抽查 64 张图片。
- 验证报告、已知限制和来源授权说明。
- 整包 SHA256；如分卷交付，包含每个分卷的 SHA256、顺序和重组说明。

本地 `127.0.0.1` 网址只对运行服务器的电脑有效，不能当作对方可直接访问的公网网址。需要公网访问时，应将交付包部署到对方指定的 Git/托管环境，并提供真实部署链接。

## 18. 浏览器安全

本工作区禁止以任何方式启动 Microsoft Edge，包括 headless、CDP、测试、截图、审计和抓取。不得关闭、卸载、禁用、杀死或重配用户个人 Edge。浏览器依赖工作只使用明确配置的隔离 Google Chrome；未配置时在创建进程前失败。

## 19. 明确不采用的做法

- 一个混合所有平台选择器并允许静默回退的导入器。
- 先全站生成，最后才第一次做基础检查。
- 只检查首页或只检查横向滚动。
- 用截图替代关键图片资源。
- 只判断链接能打开，不比较点击结果形态。
- 原站抽屉被错误生成成独立登录页。
- 用 URL、名称或来源实例 ID 代替平台永久身份。
- 只凭名称、截图或图片比例判断重复组件。
- 把 preset、version、component 和 family 混成一种“变体”。
- 原站没有手机基线却声称手机端与原站一致。
- 单元测试通过就宣布全站完成。
- 为了提速而少测页面、少点按钮或只抽查资源。
