# 自动验收标准

版本：1.1.0  
Owner：自动验收与质量团队

## 1. 验收层级

顺序固定：公共资源 → 组件 → 页面 → 全站。上层失败时不得继续标记下层通过。

## 2. 组件即时验收

每生成一个组件立即比较原站标准答案与本地结果：

- 文字内容、换行、语义和可编辑来源。
- 图片直接资源、固有尺寸、比例、裁切、焦点和清晰度。
- 容器宽高、间距、对齐、网格和层级。
- 320、360、390、768、1024、1440、1920 宽度。
- 横向溢出、右侧留白、重叠、遮挡。
- schema、preset、component kind、家族/类型/版本/实例 ID、编辑标记和空值处理。

未通过不得保存为已验收组件。

## 3. 交互验收

自动发现并实际操作所有可见的 link、button、form control 和可交互角色。每个动作比较：

- 点击前状态。
- 结果类型：页面、抽屉、弹窗、展开、标签切换、轮播、提交或数据更新。
- URL 和本站路由。
- 可见内容和关键数据变化。
- 焦点移动、Escape、关闭、背景点击和焦点返回。
- 错误、loading、成功、空态、禁用态。

只验证“可点击”或“URL 能打开”不算通过。

## 4. 页面验收

- 页面所有内部链接目标存在。
- 页面没有原站域名逃逸。
- 页面资源全部 READY 且未使用截图冒充原子资源。
- 关键文字、图片、组件顺序和交互与标准答案一致。
- 桌面与手机均通过。原站有手机基线时比较来源一致性；原站没有手机基线时，只按本平台响应式门禁检查溢出、重叠、顺序、可读性、触控和交互，禁止伪造来源手机截图或来源一致性结论。
- 账户、购物车等后台未实现能力必须显示明确受控状态，不能假成功。

## 5. 全站验收

- 路由闭包为零缺口。
- 所有页面类型至少一个代表样本通过。
- 全站菜单、页头、页脚、搜索、登录、产品、分类、购物车路径连通。
- 视觉相似度目标不能替代内容、交互、路由和可编辑性门禁。
- 95% 只能在约定截图单元、视口和计算方法下报告，并同时满足所有硬门禁。

## 6. 静态与运行时检查

- schema JSON、ID 唯一、引用存在、数量限制。
- a11y：键盘、焦点、label、alt、对比度、触控目标。
- 性能：LCP、CLS、资源大小、图片 sizes/srcset、脚本错误。
- 安全：危险 URL、任意代码、XSS、上传状态。
- locale：缺 key、fallback、RTL、长文字。

## 7. 报告与证据

每次结果记录 source URL、local URL、revision、视口、时间、浏览器、动作、预期、实际、截图/DOM/网络证据和 pass/fail。网络错误、公共资源错误、组件错误、页面错误和交互错误必须分别统计。

## 8. 禁止假通过

缺少标准答案、未点击全部交互、目标页面未生成、原站连接失败、截图单元不一致、仅首页通过、仅桌面通过、测试被跳过或进程超时，均不得宣称全站完成。

组件库验收还必须拒绝：section/theme-block 跨层级合并、按爬取顺序编号、前导零丢失、旧纯数字组件 ID 继续分配、`coco-v1-pending` 阶段出现正式家族或组件编号。

## 9. 机器报告合同

```json
{
  "auditVersion": 1,
  "siteRevision": 42,
  "status": "passed|failed|blocked",
  "startedAt": "ISO-8601",
  "finishedAt": "ISO-8601",
  "coverage": {
    "routesExpected": 0,
    "routesPassed": 0,
    "interactionsExpected": 0,
    "interactionsPassed": 0,
    "viewportsExpected": 0,
    "viewportsPassed": 0
  },
  "gates": [],
  "failures": [],
  "evidence": []
}
```

`blocked` 表示无法取得可靠标准答案或外部状态阻塞，不能按 passed 处理。每个 gate 包含唯一 ID、scope、expected、actual 和 evidence IDs。发布后台只接受同一 `siteRevision` 的 `passed` 报告。

## 10. 最终逐块自验闭环

自动验收必须执行 `09-最终导入底层执行标准.md` 的固定闭环：公共资源验收 -> 生成一个组件/页面 -> 原站与本地逐块对比 -> 检查文字、图片、尺寸、自适应 -> 逐按钮点击并比较结果 -> 检查本站路由和目标页面 -> 检查 schema 与可编辑性 -> 通过才标记已验收 -> 原子保存 -> 再做下一页 -> 整页验收 -> 全站总验收。

逐块、整页、全站是三个独立状态；后一级通过不能伪造前一级通过，单元测试通过也不能替代浏览器验收。
