# COCO 网站源码开发文档

## 1. 这份代码是什么

COCO 源码是站点专用层，不是通用抓取器，也不是验收报告。

它负责：

- COCO 页面和组件的 React/TSX 实现；
- COCO 专用样式与设计变量；
- COCO 页面交互；
- COCO 专用语言包和 DOM 适配；
- COCO 已本地化的小型图片资源。

完整静态网站位于交付目录的 `01-COCO完整网站/dist/`。源码层与通用底层合并后，形成可继续开发和重新构建的完整工程。

## 2. 与通用底层的边界

COCO 源码中不包含：

- 通用抓取、网络重试和熔断；
- 页面ID和组件身份合同；
- 通用图片冻结、字体冻结和路由闭包；
- 通用组件验收、页面验收和发布门禁；
- Shopify、Wix和普通外网的适配器选择逻辑。

这些能力全部属于 `03-通用导入器底层代码/`。

COCO 源码中保留：

- `src/components/`：COCO 组件实现；
- `src/pages/`：COCO 页面入口；
- `src/interactive/`：COCO 交互运行时；
- `src/localization/majestic-pack.js`：COCO/站点语言内容包；
- `src/localization/replay-adapter.js`：COCO DOM 语言适配；
- `src/restored-assets/`：源码直接引用的小型本地资源；
- 根级 TSX、CSS 和组件注册文件。

共享的 `src/localization/locale-service.js` 属于通用底层，不属于COCO。

## 3. 主要目录

### 3.1 `src/components/`

这里保存网站可复用的组件实现。组件按真实区域和功能命名，不以截图序号代替功能名称。

组件应继续遵守：

- 一个组件只负责一个清晰功能；
- 内容、图片、字体、颜色、间距和行为通过设置数据进入组件；
- 不把客户内容写死在编辑器代码里；
- 图片记录原图尺寸和实际展示/裁切尺寸两层证据；
- 组件根节点保留稳定组件身份；
- 相同结构与功能复用同一组件类型，不重复造组件。

### 3.2 `src/pages/`

这里保存网站页面级组合。页面负责排列组件，不复制组件内部实现。

每个页面必须具备：

- 永久的平台页面数字ID；
- 来源URL；
- 可选的来源页面ID；
- 页面使用的组件实例顺序；
- 本站路由；
- 桌面和移动端共用的数据。

### 3.3 样式文件

- `src/design-tokens.css`：颜色、字体、尺寸等设计变量；
- `src/layout.css`：整体布局；
- `src/component-styles.css`：组件样式；
- `src/index.css`：站点入口样式。

响应式通过同一套组件数据和CSS完成，不另外复制一套手机版内容。

### 3.4 交互与语言

- `src/interactive/`：抽屉、菜单、弹窗、轮播等交互；
- `src/localization/majestic-pack.js`：站点翻译数据；
- `src/localization/replay-adapter.js`：把翻译内容绑定到页面结构。

点击结果必须与原站交互结果一致。例如原站在当前页面打开抽屉，本地也必须打开抽屉，不能只保证链接能打开。

## 4. 组合成完整开发工程

COCO 源码是站点覆盖层。使用交付根目录的 `组合源码.ps1`：

```powershell
.\组合源码.ps1
```

脚本会：

1. 新建一个空的组合工程；
2. 先复制通用底层；
3. 再覆盖COCO专用源码；
4. 保留两套原始目录不变；
5. 输出可执行 `npm ci`、`npm test` 和 `npm run check` 的工程。

## 5. 修改组件

修改组件时按以下顺序：

1. 找到对应 `src/components/*.tsx` 文件；
2. 修改组件结构或数据绑定；
3. 同步修改对应CSS；
4. 确认文字、图片、字体、颜色、尺寸和行为仍可由数据控制；
5. 在组合工程运行测试和TypeScript检查；
6. 只重建受影响组件和页面；
7. 通过后再进入正式网站。

## 6. 修改页面

页面修改不应复制组件代码。正确做法是：

- 调整页面的组件实例顺序；
- 修改组件实例设置；
- 增加或删除组件实例；
- 保持页面ID不变；
- 重新验收受影响页面和本站路由。

## 7. 图片与资源

每张图片区分：

1. 原始资源层：文件、原始宽高、格式、哈希；
2. 展示层：容器宽高、`object-fit`、`object-position`、裁切和响应式状态。

不能拿原图比例直接代替页面展示比例。裁切图必须保留原图证据和展示证据。

## 8. 可编辑性

COCO组件需要支持的可编辑内容包括：

- 文字、富文本、链接和按钮；
- 图片、视频、焦点位置和裁切方式；
- 字体、字号、字重、行高和字间距；
- 颜色、背景、边框和圆角；
- 宽度、高度、间距和对齐；
- 轮播、翻页、自动播放和显示条件；
- 组件和小组件的添加、删除、复制与排序。

编辑器读取组件schema生成设置面板，业务规则不能写死在编辑器前端。

## 9. 验证要求

COCO源码变更后至少执行：

```powershell
npm ci
npm test
npm run check
```

页面交付还必须通过：

- 文字、图片、尺寸和响应式；
- 逐按钮实际点击结果；
- 本站路由闭包；
- schema和可编辑性；
- 桌面端和移动端；
- 组件、页面和全站三层门禁。

## 10. 浏览器安全

本机禁止自动化启动Microsoft Edge。浏览器测试只能使用隔离的Chrome/Chromium，并在启动前通过安全检查。

## 11. 不属于源码的内容

以下内容不放入COCO源码目录：

- 完整静态网站 `dist`；
- 历史修复脚本；
- 临时截图和浏览器缓存；
- 验收报告；
- 交付压缩分卷；
- `node_modules`；
- 旧版本候选。
