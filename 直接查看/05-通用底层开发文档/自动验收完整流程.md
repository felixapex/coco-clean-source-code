# 网站导入自动验收流程

版本：1.0.0  
原则：边生成边验收，通过才保存；全站验收只确认遗漏，不能第一次发现基础错误。

## 1. 总闭环

`公共资源验收 → 抓取一个组件 → 生成一个组件 → 原站与本地逐块对比 → 检查文字、图片、尺寸、层级、响应式和可编辑性 → 逐控件点击并比较结果 → 检查本站路由和目标页面 → 通过才保存 → 生成一页 → 立即验收一页 → 全站总验收`

任何门禁失败都写问题清单并阻止晋级，禁止以警告、跳过或历史报告代替通过。

## 2. 错误分类门禁

输入：抓取或验收错误。  
动作：分类为网络、公共资源或页面错误。  
通过：错误具有稳定分类、签名、来源和影响范围。  
失败输出：`unclassified-error`，停止自动修复。  
证据：任务状态表和 `validation-issues.json`。

网络错误只影响来源主机；公共资源错误阻止所有依赖页面；页面错误只隔离单页。

## 3. 公共资源前置门禁

输入：页头、页脚、Logo、菜单图、字体、公共样式和脚本。  
动作：先停用隐藏图片和已冻结视频的失效远程地址，再从组件资产清单提取真实活动资源；下载一次，验证 MIME、字节、SHA256、图片尺寸、字体可用性和 CSS 嵌套引用闭包。图片本体已经本地化时仍要检查并清除 `srcset`、`data-src` 等远程覆盖属性。每个成功资源立即写入可恢复 manifest。  
通过：全部资源存在、本地可读、内容类型正确且没有未授权外部引用。  
失败输出：`waiting-public-resource`，禁止开始全站页面抓取。  
证据：恢复 ledger、`remote-assets-manifest.json`、源码范围的 `source-remote-asset-preflight.json`、候选站范围的 `stage-remote-asset-preflight.json` 和组件资产报告。测试构建、源码预检和候选站审计不得覆盖不同范围的正式证据。

同一资源主机连续3次出现相同网络错误时必须按主机熔断；剩余 URL 标记等待该公共资源主机，不再逐条重复等待。预检报告绑定源页面清单哈希；源清单未变化时，正式构建直接复用报告。报告仍有失败时，构建必须在创建候选目录前失败，不能先生成全站再检查。

## 4. 代表样本稳定门禁

输入：至少8类页面：首页、分类页、产品页、博客页、普通内容页、搜索页、登录交互页、复杂菜单页。  
动作：1–2路并发连续跑3遍。  
通过：三遍的资源、组件、布局、交互和路由结果一致且全部通过。  
失败输出：保留失败轮次、截图、DOM、网络和交互差异；不得扩容。  
证据：代表页稳定性报告。

## 5. 并发与熔断门禁

输入：代表样本通过的任务队列。  
动作：并发按 `2 → 3 → 4` 逐档扩大。  
通过：当前档失败率没有高于上一档。  
失败输出：自动降档；连续3页相同网络错误或10页网络失败超过20%时停止整批。  
证据：并发档位、失败率、主机熔断和恢复点。

## 6. 组件即时验收

输入：一个来源组件及其来源名称、DOM、样式、资源和交互。  
动作：

1. 核对来源组件名与实际功能；
2. 提取层级、文字、图片、视频、按钮和状态；
3. 转成 section、theme blocks、settings、presets；
4. 与来源逐块比较；
5. 点击组件内所有可交互控件并比较结果。

通过：内容、功能、层级、尺寸、响应式、交互和可编辑合同全部一致；名称匹配或已记录重命名证据。  
失败输出：组件留在候选区，不进入中央组件库。  
证据：组件 dossier、指纹、点击结果和可编辑门禁。

## 7. 文字门禁

输入：所有可见标题、正文、按钮、标签和表单提示。  
动作：比较内容、字体角色、字号、字重、行高、字间距、颜色、对齐、换行和遮挡。  
通过：没有乱码、重叠、截断和写死的可见业务文字；可编辑文字能映射到 setting、全局设置、资源字段或多语言键。  
失败输出：具体文本、位置、来源和本地值。  
证据：文字清单、字体证据和截图差异。

## 8. 图片和层级门禁

输入：页面全部真实图片。  
动作：验证来源文件、SHA256、固有尺寸、渲染尺寸、容器尺寸、祖先深度、比例、`object-fit`、焦点和裁切。  
通过：关键图片直接读取；没有页面矩形截图冒充；没有未解析外链；显示比例与来源表现一致；手机端不溢出。  
失败输出：图片 URL/文件、尺寸两层证据、容器路径和差异。  
证据：图片 manifest、几何属性和资源审计。

## 9. schema 与可编辑性门禁

输入：section schema、theme blocks、实例 settings 和标记后的 DOM。  
动作：检查字段、ID 唯一性、类型、presets、数量、嵌套、空值、`visible_if` 和数据标记。  
通过：编辑器可完全由 schema 生成面板；所有可见可编辑值双向绑定；图片/video/product 等空值不报错；没有非法 default。  
失败输出：组件 ID、block ID、setting ID 和失败类型。  
证据：`editable-contract-audit.json` 和组件包验证记录。

## 10. 交互结果门禁

输入：该页所有可见链接、按钮、菜单、筛选、轮播、抽屉、弹窗和表单。  
动作：按来源顺序逐一真实点击，比较点击前后 URL、可见层、DOM 状态和目标内容；每个控件后恢复干净状态。  
通过：本地结果类型和来源一致。例如来源是登录抽屉，本地也必须是抽屉且 URL 不变，不能只生成可打开的登录页。  
失败输出：控件身份、点击步骤、预期、实际和截图/DOM。  
证据：交互点击报告。

相同代码和相同行为签名的公共组件可只完整点击一个唯一行为版本，但每页控件仍必须验证其内容、目标和绑定存在；页面特有链接不得因组件复用而跳过。

## 11. 路由闭包门禁

输入：菜单、按钮、分类、产品、面包屑和程序生成链接。  
动作：归一化目标，检查是否本站路由、目标页面是否已生成、查询参数是否保留。  
通过：禁止来源站外链逃逸；所有本站目标存在；未生成目标为零。  
失败输出：来源页、控件、目标和失败原因。  
证据：route-link audit 和 published route closure。

## 12. 页面即时验收

输入：一个已经通过组件门禁的候选页面。  
动作：桌面和手机分别检查文字、图片、尺寸、层级、右侧留白、横向滚动、遮挡、全部控件和目标页面。  
通过：该页所有门禁通过后才写入正式候选；失败只重做这一页和变化组件。  
失败输出：页面状态改为 `page-content-failed`，保留已通过页面。  
证据：页面哈希、桌面/手机报告和问题清单。

## 13. 响应式门禁

输入：同一页面数据和响应式样式。  
动作：至少在桌面、平板和手机宽度检查布局边界、文字、图片、菜单和交互。  
通过：没有固定页面宽度、右侧空白、水平溢出、文字重叠或不可点击控件；手机端与桌面端共用同一内容数据。  
失败输出：路由、视口、元素路径和溢出像素。  
证据：responsive layout report。

## 14. 可恢复任务状态

每个 URL 和组件保存状态：`pending`、`completed`、`network-deferred`、`page-content-failed`、`waiting-public-resource`、`accepted`。状态同时保存输入哈希、输出哈希、尝试次数、错误签名和证据路径。页面生成完成后立即原子写入页面 HTML、关联资产文件、源/输出 SHA256、每个资产 SHA256 和完成状态；只把状态写成 `completed` 而没有对应文件与哈希属于失败。

中断后只继续未完成、失败或输入哈希变化的项目；已通过且哈希未变化的结果不得重做。

写入成功不能单独代表文件有效。页面、检查点和资产必须在原子改名之前和之后各读回一次并逐字节核对；读回不一致时最多重试3次，仍不一致立即停止，禁止把页面标记为复用或完成。

候选页面已经完整落盘时，只允许使用“原地继续”进入尚未完成的组件分析和发布门禁。程序先核对检查点与源输入哈希，然后读取现有页面；禁止清空候选、复制全站或从第一页重新生成。

恢复和总资产清点必须采用有界文件并发；出现 `EMFILE` 视为底层并发错误，不能把页面标记失败，也不能清空已经落盘的页面检查点。修复后从原检查点继续资产审计。

## 15. 全站总验收

输入：所有已经逐页通过的候选页面。  
动作：

- 全站桌面、平板和手机布局；
- 全路由和目标页闭包；
- 全部唯一交互行为；
- 全资源本地化和哈希；
- 全组件/页面/全站三层门禁；
- 安装、构建、启动和关键页 HTTP 冒烟；
- 全文件 SHA256。

通过：问题清单中阻塞项为0，构建原子晋级成功，最终包自身可安装、构建和启动。  
失败输出：不替换上一个正式版本，不生成“完整”声明。  
证据：综合验证报告、最终 manifest 和 `SHA256SUMS.txt`。

已完成候选的正式晋级必须读取同一版本的检查点完整性、可编辑合同、路由闭包、图片恢复、统一问题清单和组件库证据。任一证据失败或候选路径不匹配时禁止晋级；全部通过后只进行目录原子改名，不得借“发布”再次生成或复验全站。

## 16. 通过声明规则

只有本次运行的新证据可以支持本次完成声明。旧截图、旧报告、局部测试、代码已修改、进程退出0中的任一项，都不能单独证明全站完成。报告必须同时给出命令、时间、输入版本、通过数、失败数和证据路径。
