# 网站导入底层开发文档

版本：1.0.0  
适用代码：本目录 `package.json` 标记的 `matbox-reconstructed-site-poc@2.9.0`  
目标读者：导入器开发、组件开发、编辑器前端、测试与发布流水线开发

## 1. 目标和责任边界

本项目把一个已授权或仅用于版式学习的网站转换为可本地运行、可组件化、可编辑、可验证的网站数据。底层采用两层结构：

1. 平台适配层负责识别 Shopify、Wix 或普通外网的来源特征、路由和原组件名称。
2. 共享核心负责抓取安全、页面永久 ID、资源本地化、组件命名与去重、可编辑契约、生成、断点恢复和验收。

编辑器不在本项目实现。底层输出 schema、sections、theme blocks、settings、presets、模板 JSON 和 DOM 定位标记；编辑器只读取这些数据生成设置面板。后端商品、库存、订单和账户数据也不由导入器伪造。

## 2. 唯一正式入口

| 命令 | 用途 | 成功输出 | 失败行为 |
| --- | --- | --- | --- |
| `npm ci` | 按锁文件安装依赖 | 完整 `node_modules` | 依赖或完整性错误时非零退出 |
| `npm run check` | TypeScript 静态检查 | 0 错误 | 任一类型错误非零退出 |
| `npm test` | 全部底层与回归测试 | 0 失败 | 任一测试失败非零退出 |
| `npm run build` | 原子构建正式 `dist/` | 全部门禁通过后替换 `dist/` | 候选失败时保留原 `dist/` |
| `npm run promote:stage -- --stage=<目录>` | 把已完成候选直接晋级为正式网站 | 证据全部通过后原子替换 `dist/` | 不重新生成页面；任一证据失败则保留候选和原 `dist/` |
| `npm start` | 启动本地网站 | 默认 `127.0.0.1:4173` | `dist/` 缺失或端口错误时失败 |
| `npm run rebuild:web -- <URL>` | 普通外网导入 | 完整流水线报告 | 平台、网络、资源或验收失败时停止 |
| `npm run rebuild:shopify -- <URL>` | Shopify 专属导入 | Shopify 证据和专属路由结果 | 不允许回退成普通外网导入 |
| `npm run rebuild:wix -- <URL>` | Wix 入口 | 当前必须失败关闭 | Wix 未实现时不得伪装成功 |

`scripts/run-20-minute-pipeline.mjs` 是导入总编排入口；名称是历史名称，不构成“必须20分钟完成”的承诺。实际时间写入阶段计时和历史记录。

## 3. 目录结构

### 3.1 抓取核心 `src/import-core/`

- `capture/chromium-capture.mjs`：隔离 Chromium/Chrome 会话、页面抓取、页面实际变化监听、图片与组件几何证据。
- `capture/observed-page-readiness.mjs`：按网络、DOM、图片、字体和尺寸稳定状态结束等待，禁止固定等待冒充就绪。
- `capture/capture-failure-classifier.mjs`：区分网络错误、公共资源错误和页面错误。
- `capture/capture-failure-policy.mjs`：重试、熔断和失败保留策略。
- `capture/persistent-resource-cache.mjs`：跨页面复用已验证资源，不复用页面结果。
- `capture/interaction-stability.mjs`：交互前后的稳定状态判断。
- `pipeline/adaptive-capture-queue.mjs`：并发从低档逐步扩容，失败率升高时降档。
- `pipeline/persistent-worker-pool.mjs`：隔离浏览器工作进程并持久化任务状态。
- `pipeline/stage-timing.mjs`：抓取、分析、转换、生成、验收的分阶段计时。
- `security/browser-request-guard.mjs`：浏览器请求出站规则。
- `security/url-policy.mjs`：URL、协议、主机和本站路由安全策略。

### 3.2 组件与页面标准 `src/import-foundation/`

- `page-identity.mjs`：平台永久数字页面 ID；来源页面 ID、URL、名称独立保存。
- `component-dossier.mjs`：组件来源名、实际功能、结构、行为、响应式、schema 和证据档案。
- `component-function-evidence.mjs`：从可见内容和交互证据判断实际功能。
- `component-naming.mjs`：来源名匹配时保留；不匹配时按真实区域和功能命名。
- `component-fingerprints.mjs`：结构/行为、功能、响应式和 schema 指纹。
- `component-classifier.mjs`：判断新组件、已存在组件或名称冲突。
- `central-component-library.mjs`：组件家族与复用登记。
- `component-package.mjs`：生成可独立交付的组件包、资产清单和验证记录。
- `editor-data-contract.mjs`：编辑器可读取的数据契约。
- `resource-contract.mjs`、`resource-freezer.mjs`：资源来源、哈希和本地冻结。
- `verification-gates.mjs`、`verified-promotion.mjs`：通过才晋级正式结果。

### 3.3 构建和验证 `scripts/`

- `build.mjs`：候选目录、资源预检、页面处理、可编辑门禁、组件库、页面组装、路由检查和原子发布。
- `lib/disk-backed-import-foundation.mjs`：按批写 JSONL，避免全站组件对象常驻内存。
- `lib/editable-component-contract.mjs`：把真实文字、图片、按钮、视频和层级转成 theme blocks 与双向绑定。
- `lib/component-schema-contract.mjs`：验证 Shopify OS 2.0 风格 schema 和图片证据。
- `lib/local-component-geometry.mjs`：图片固有尺寸、渲染尺寸、容器层级、裁切和响应式证据。
- `lib/recovered-image-publisher.mjs`：验证恢复图片哈希，并在组件分析前本地化。
- `lib/image-dimensions.mjs`：不依赖浏览器读取 PNG、JPEG、WebP、GIF、SVG 固有尺寸。
- `lib/route-link-audit.mjs`：本站路由、目标页面和外链逃逸检查。
- `enrich-local-component-geometry.mjs`：只对变化页面定向重测几何证据。
- `audit-all-interactions.mjs`：真实点击并记录交互结果。
- `audit-responsive-layout.mjs`：桌面/平板/手机响应式门禁。
- `compile-verification-evidence.mjs`：合并组件、页面、路由、交互和响应式证据。

## 4. 平台适配规则

三个入口代码分开，输出契约统一：

- Shopify：读取 Shopify 主题/页面证据和原组件类型；原名称与实际功能匹配就保留，不匹配就重新命名。
- 普通外网：读取 DOM、前端属性和运行时结果；有可信组件名则核对复用，没有或不匹配则按实际功能命名。
- Wix：未来实现独立识别器；未实现前失败关闭。

共享核心不能猜平台，也不能把一个平台的特殊规则写进公共组件分类器。

## 5. 页面身份合同

每个页面保存：

- `platformPageId`：平台生成、永久不变的纯数字 ID；相同页面重新导入继续使用。
- `sourcePageId`：原站存在则保存，不存在则为空。
- `sourceUrl`：来源 URL，只作来源和重新导入匹配证据。
- `sourceName`：原页面名称。
- `route`：本站路由，不能代替页面 ID。

页面 ID 映射输出到 `component-library/page-identity-registry.json`。任何重建都必须先读取已有登记，禁止给同一页面重新编号。

## 6. 组件身份、命名和复用

组件不能只靠名称或截图判重。复用至少同时比较：

1. 实际功能；
2. DOM/层级和交互结构；
3. 桌面与手机响应式行为；
4. schema 设置合同；
5. 图片比例、裁切和容器关系；
6. 行为结果。

来源组件名称与网页实际功能匹配时保留；不匹配时记录原名、实际功能、判定证据和新名称。相同组件只在中央组件库保存一次，各页面只保存组件实例、设置和顺序。

## 7. Shopify OS 2.0 风格可编辑合同

页面模板是 JSON，包含 `sections` 和 `order`；页面最多25个 section。页头和页脚使用 section groups。section 最多50个 theme blocks，允许用更低的 `max_blocks` 限制。

每个 section schema 必须包含 `name`、`tag`、`settings`、`blocks: [{"type":"@theme"}]`、`max_blocks`、`presets`，以及 `enabled_on` 或 `disabled_on`。`limit` 只允许1或2。section 不得混用内联 block 和 theme block。

基础 theme blocks 包括标题、正文、按钮、图片、视频和分组，每个都必须至少有一个 preset。可见内容进入实例 settings，不得把来源图片写成 `image_picker.default`。

DOM 定位标记：

- section 根：`data-section-id`、`data-section-type`
- block 根：`data-block-id`、`data-block-type`
- 可编辑值：`data-setting`

字体、字号、字重、行高、字间距、颜色、对齐、按钮样式、圆角、上下间距、图片比例、填充方式、焦点位置都由 schema/settings 控制。电脑版、平板和手机版共用一份内容数据。

## 8. 图片的两层证据

图片必须同时保存：

1. 来源层：来源地址、本地文件、SHA256、MIME、固有宽高和固有比例。
2. 显示层：渲染宽高、容器宽高、容器祖先深度、`object-fit`、`object-position`、裁切、溢出和视口。

不能用未裁切原图比例代替页面显示比例，也不能只检查图片直接父元素。容器选择必须向上查找，直到找到真正包含或裁切图片的最近祖先。动态模板中没有真实 `src` 的占位图片不得进入组件库。

恢复图片必须在组件分析之前完成；恢复时同时写入已验证的固有尺寸。图片已经存在于本地 `src` 或内嵌 data URL 时，仍必须检查 `srcset`、`data-src`、`data-lazy-src`、`data-original`、`data-srcset` 和 `data-lazy-srcset`；这些懒加载或响应式属性不得继续保留同一图片的远程覆盖地址。外部 URL、页面矩形截图或无尺寸占位图不能通过图片门禁。

## 9. 构建和原子发布

`scripts/build.mjs` 固定顺序：

1. 公共资源和阻塞报告预检；真实活动远程资源必须先本地化，失败报告与当前源页面清单哈希一致时立即停止；
2. 创建唯一 `.dist-staging-<pid>` 候选；
3. 页面净化、本站路由转换、恢复图片本地化和资产外置；
4. 分批写入 import foundation，不把全站对象留在内存；
5. 可编辑合同门禁；
6. 组件分类、组件包和页面组装；
7. 路由、资源、组件和交付门禁；
8. 全部通过后原子替换 `dist/`。

任一步失败都不能覆盖上一个可用 `dist/`。失败候选可用于诊断，但不得进入交付包。每个页面完成时必须通过 `writeBuildPageCheckpoint` 原子落盘：页面 HTML、源输入 SHA256、输出 SHA256、组件资产文件、资产 SHA256 和 `completed` 状态缺一不可。所有检查点和资产写入都必须“临时文件写入 → 读回逐字节核对 → 原子改名 → 最终文件再次读回核对”，最多重试3次，不能只凭 `writeFile` 成功就标记完成。

恢复构建使用 `--resume-from=<失败候选>`；旧候选缺少检查点时，还需用 `--resume-assets-from=<含完整资产清单的候选>` 做一次校验迁移。只有源、输出和全部资产哈希一致的页面才允许跳过，第一张未完成或哈希变化的页面必须重新生成。候选已经完整落盘、只剩组件分析或发布时，使用 `--continue-existing-stage=<候选>`：先核对现有页面和源输入哈希，然后原地继续，不删除、不复制、不重新生成页面，也不重复下载已验证公共资源。

组件分析前和正式晋级前分别生成 `build-checkpoint-integrity-after-pages.json` 与 `build-checkpoint-integrity-final.json`。两份报告必须同时满足：HTML 类型正确、检查点有效、输出哈希一致和失败数为0。最终晋级由 `scripts/promote-existing-stage.mjs` 读取全部门禁证据并调用原子目录晋级，不得为了发布重新跑全站。

## 10. 错误分类、重试和熔断

- 网络错误：连接重置、超时、限流；可重试并按主机熔断。
- 公共资源错误：页头、页脚、菜单图、字体、公共脚本或样式；失败一次停止依赖页面。
- 页面错误：单页内容、图片、布局、路由或交互失败；只隔离该页。

连续3页出现相同网络错误立即停止整批；10页中网络失败超过20%立即停止；已完成结果和哈希证据保留。任务状态至少包括未开始、已完成、网络暂缓、页面失败、等待公共资源和已验收。

远程资源恢复使用两层缓存：捕获期 `.resource` 缓存和已验证冻结资产 manifest。HTML 注释、隐藏图片、来源追踪属性、未被组件使用的远程字体导入和已经有本地画面的视频不能被误判为活动资源。活动资源成功后立即保存文件、字节数和 SHA256；单项失败不得使已成功文件丢失。同一主机连续3次失败后打开主机熔断。源码门禁写入 `artifacts/full-site-audit/source-remote-asset-preflight.json`，已生成候选站的组件包资源审计写入 `artifacts/full-site-audit/stage-remote-asset-preflight.json`；两个证据范围不得共用或覆盖同一报告。源码门禁未通过时禁止创建或替换候选网站。

## 11. 并发和性能

先用1–2路跑8类代表页三遍；三遍全过后按 `2 → 3 → 4` 扩容。失败率上升自动降档。页面之间可并行，单页内部交互按来源顺序执行。禁止多个工作进程共享浏览器配置目录。

生成计时写入：

- `artifacts/full-site-audit/generation-timing.json`
- `artifacts/full-site-audit/generation-timing-history.jsonl`

缓存只复用已验证公共资源和未变化文件证据，不得因组件代码相同而跳过页面特有内容、链接和目标检查。

资产清单读取必须使用有界并发，默认最多同时读取32个文件；禁止对全站资产直接使用无上限 `Promise.all`，否则大型网站会触发 Windows `EMFILE`。断点恢复期间相同资产只核验和复制一次，不得因多个页面共享同一资产而重复打开文件。

远程资源预检工具：

- `node scripts/preflight-active-remote-assets.mjs --from-package-audit`：消费组件包门禁给出的真实远程资源清单，下载、递归冻结 CSS 依赖并生成可恢复报告；
- `node scripts/preflight-active-remote-assets.mjs --from-package-audit --inventory-only`：只用已验证本地缓存核对候选站资源，不访问网络；用于毫秒级确认仍缺哪些真实字节；
- `node scripts/preflight-active-remote-assets.mjs --stamp-only`：把现有报告绑定到当前源页面清单哈希，不发起网络请求；
- `node scripts/audit-stage-component-packages.mjs --stage=<候选目录>`：把已验证冻结资源映射回组件后重新审计全部组件包。
- `node --expose-gc scripts/build.mjs --stage-only --staging-dir=<新候选> --resume-from=<失败候选>`：核验磁盘检查点后只生成未完成或输入变化页面；不得清空并重做已经通过且哈希一致的页面；
- `--resume-assets-from=<旧完整候选>`：仅用于把旧版无 SHA256 检查点的页面迁移为新检查点，迁移时重新计算并落盘资产 SHA256。
- `--continue-existing-stage=<完整候选>`：候选页面已完成时原地继续组件分析；禁止和 `--staging-dir`、`--resume-from` 混用。
- `npm run promote:stage -- --stage=<完整候选>`：读取已保存的最终门禁并原子晋级，绝不重新生成或重新复验页面。

## 12. 主要环境变量

- `MATBOX_CHROMIUM_PATH`：隔离 Chrome 路径；若指向 `msedge.exe` 必须失败。
- `MATBOX_SOURCE_URL`、`MATBOX_LOCAL_ORIGIN`：来源站和本站地址。
- `MATBOX_IMPORT_PLATFORM`：`shopify`、`web` 或 `wix`。
- `MATBOX_WORKERS`、`MATBOX_SOURCE_WORKERS`、`MATBOX_AUDIT_WORKERS`：阶段并发。
- `MATBOX_RESUME`：断点恢复。
- `MATBOX_ROUTE_CLOSURE_PASSES`：路由闭包最大轮数。
- `MATBOX_BUILD_ANALYSIS_BATCH_SIZE`：构建分析批大小。
- `MATBOX_DIST_DIR`：验收目标目录。
- `MATBOX_PERSISTENT_RESOURCE_CACHE_DIR`：公共资源缓存目录。
- `MATBOX_RESPONSIVE_WORKERS`、`MATBOX_INTERACTION_WORKERS`：响应式与交互并发。
- `PORT`、`HOST`：本地静态服务地址。

环境变量只调节运行方式，不能关闭核心门禁或降低通过标准。

## 13. 浏览器安全

本工作区禁止自动化启动 Microsoft Edge。浏览器代码在进程创建前检查可执行文件名并失败关闭。自动化只能使用隔离 Chrome、独立用户数据目录；不得终止、修改、复用或重新配置用户个人浏览器。

## 14. 修改底层代码的标准流程

1. 写最小失败测试并确认真的失败；
2. 找到数据从来源到失败门禁的完整路径；
3. 只修改根因；
4. 运行针对测试；
5. 运行 `npm run check`；
6. 运行完整 `npm test`；
7. 运行代表页构建；
8. 最后运行完整构建和交付验证。

不得用放宽阈值、删除失败项、静态假数据或“应该可以”替代验证。

## 15. 新增平台或组件类型

新增平台时只增加适配器和平台证据测试，仍输出统一页面、资源和组件档案。新增可编辑能力时更新组件 schema 和通用 theme block，编辑器通过 schema 自动出现设置项；禁止在编辑器里为单个网站写特殊逻辑。

## 16. 故障排查

- 构建内存上涨：检查是否把全站页面/组件对象留在数组；优先使用 JSONL 和批处理。
- 图片恢复后仍缺证据：检查本地化是否发生在组件分析前，以及固有宽高是否写回。
- 页面显示溢出：同时检查图片、直接父级、包含祖先和裁切祖先。
- 目标页 404：检查路由发现、URL 归一化、目标生成和路由闭包报告。
- 弹窗被做成独立页面：比较点击前后 URL、DOM 和可见层结果，不能只看链接是否可打开。
- 局部通过但交付失败：以最终干净包内的安装、构建、启动和全文件哈希为准。
