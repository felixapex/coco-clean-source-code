# 底层开发说明

完整开发文档见 [COMPLETE-DEVELOPER-GUIDE.md](./COMPLETE-DEVELOPER-GUIDE.md)。本文件保留为快速入口，完整交付不得只提供本摘要。完整版本超过 1,300 行，并包含通用底层、COCO 源码、测试和排除项的逐文件索引。

## 1. 分层

项目采用“平台适配层 + 共享底层核心”：

- 平台适配层识别 Shopify、Wix 或普通网站的来源结构、原始组件名称和路由。
- 共享核心负责页面 ID、组件化、可编辑数据、资源恢复、本站路由、构建和验收。
- 平台识别不能混在共享核心中；共享的验证和恢复规则也不能在每个平台重复实现。

## 2. 正式入口

- `scripts/run-20-minute-pipeline.mjs`：完整导入流水线。
- `scripts/build.mjs`：候选网站构建和构建前门禁。
- `scripts/serve.mjs`：本地静态网站服务。
- `scripts/resume-image-recovery.mjs`：图片断点恢复，只处理未完成资源及变化页面。
- `scripts/compile-verification-evidence.mjs`：合并组件、页面、响应式、交互、路由和可编辑性证据。

## 3. 自包含代码边界

- 抓取核心位于 `src/import-core/`，组件与页面标准位于 `src/import-foundation/`。
- `scripts/`、`src/` 和 `tests/` 禁止通过相对路径读取本项目目录外的代码。
- 第三方包必须写入 `package.json` 和 `package-lock.json`，不得直接读取其他项目的 `node_modules`。
- `tests/self-contained-source.test.mjs` 是硬门禁；移动或单独交付本目录后，代码仍应能通过 `npm ci` 安装。
- 浏览器测试默认读取唯一候选 `dist/`；需要重新构建测试候选时必须显式设置 `MATBOX_TEST_BUILD=1`。

## 4. 页面与组件数据

- 每个页面拥有平台永久数字 ID；来源页面 ID、URL 和原页面名称单独保存。
- 页面由 sections、theme blocks、settings、presets 和 JSON template 组成。
- 页面元素通过 `data-section-id`、`data-section-type`、`data-block-id`、`data-block-type` 和 `data-setting` 与编辑器设置对应。
- 图片保存来源、固有尺寸、渲染尺寸、容器尺寸、比例、裁切和可编辑字段。
- 文字保存内容、字体、字号、字重、行高、颜色、对齐和可编辑字段。
- 组件名称优先使用来源名称；名称与实际功能不符时按真实区域和功能重新命名。
- 相同组件必须通过结构、功能、比例、设置契约和行为签名判断，不能只看名称。

## 5. 增量闭环

执行顺序固定为：

`抓取标准答案 → 生成一个组件/页面 → 立即比较 → 验证内容、图片、尺寸、响应式、交互、路由和可编辑性 → 通过才保存 → 继续下一项 → 全站汇总`

已通过且文件哈希未变化的证据继续有效。只重跑新增、失败或哈希变化的组件和页面。

## 6. 图片恢复

- 缓存、网络、组件库和历史组件恢复证据统一合并。
- 连续三次相同网络错误后对来源主机熔断。
- 恢复脚本可重复执行；已经本地化的图片不会再次写入。
- 恢复成功后只重测实际变化页面。
- 图片来源未解决时，`scripts/build.mjs` 在昂贵构建前返回 `unresolved-source-images`。
- 页面变化而阻塞证据未更新时返回 `stale-image-recovery-blocker-report`。

## 7. 代码质量

- 功能和修复必须先有失败测试，再修改实现。
- 任何门禁失败都不能通过降低标准、占位图或页面截图伪造成功。
- 断点状态和问题清单必须持久保存，中断后不得从头重跑。
- 后端业务数据不写死在编辑器或组件中。

## 8. 浏览器安全

本机禁止自动化启动 `msedge.exe`。所有浏览器相关脚本必须拒绝 Edge，并使用隔离 Chrome。不得终止、修改或复用用户的个人浏览器配置。
